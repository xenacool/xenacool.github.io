BevyGradmesh Documentation

Introduction

BevyGradmesh is a procedural mesh generation library for Bevy that provides clean APIs for creating 3D primitives with gradient shading, inspired by Freya Holmér’s work.

What It Solves

Instead of manually creating mesh assets for every shape, BevyGradmesh generates watertight geometry at runtime with proper normals and UVs. Combined with dual-directional gradient materials, you get stylized 3D-looking characters and objects without any external assets.

Every procedural primitive with dual-directional gradient shading, drawn without PBR. Run cargo run --example shapes to reproduce it.

Key Concepts

  • Shapes: Procedural primitives (spheres, cuboids, cylinders, etc.) generated at runtime
  • Styles: Gradient materials with dual-directional or dual-radial shading
  • Modes: Four rendering modes (direct, immediate, retained, batched) for different use cases
  • Performance: GPU instancing, LOD, frustum culling, and dirty tracking for rendering thousands of shapes

Design Philosophy

BevyGradmesh follows these principles:

  1. Zero external assets: Everything is generated procedurally
  2. Bevy-native: Outputs standard Mesh assets and Bevy materials (GradMeshMaterial extends StandardMaterial; the 2D, SDF and standalone backends need no PBR)
  3. Performance-first: GPU instancing and dirty tracking minimize draw calls
  4. Flexible: Multiple rendering modes for different patterns

Key Terms

  • Gradient direction: A 3D vector defining which axis the gradient runs along. Vertices on one side of the shape get the dark color; vertices on the opposite side get the light color.
  • OKLAB: A color space designed so that equal distances correspond to equal perceived color differences. Gradients in OKLAB look smoother and more natural than linear RGB interpolation. OKLCH is the same space in polar form (lightness, chroma, hue), so blends sweep around the hue wheel.
  • Blend mode: How a shape’s color combines with what’s behind it. Common modes include opaque (solid, no transparency), transparent (alpha-blended), additive (colors add together, creating a glow effect), multiplicative (colors multiply, darkening the result), screen (the opposite of multiply, lightening the result), and dither (uses a pattern to simulate intermediate alpha levels).
  • PBR (Physically-Based Rendering): A shading model that simulates how light interacts with real-world materials. Parameters include roughness (how smooth or rough a surface is), metallicity (whether a surface is metallic or dielectric), and emissive (light the material emits on its own, like a glowing screen).
  • Detail level: Controls the number of vertices and triangles in a generated mesh. Higher detail produces smoother curves but uses more GPU memory and processing.

Getting Started

Installation

Add bevy_gradmesh to your Cargo.toml:

[dependencies]
bevy = "0.20"
bevy_gradmesh = "0.3"

Your First Shape

use bevy::prelude::*;
use bevy_gradmesh::{GradMeshMaterial, GradMeshPlugin, Shape, ShapeDetail, dual_directional};

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_plugins(GradMeshPlugin)
        .add_systems(Startup, setup)
        .run();
}

fn setup(
    mut commands: Commands,
    mut meshes: ResMut<Assets<Mesh>>,
    mut materials: ResMut<Assets<GradMeshMaterial>>,
) {
    // Camera
    commands.spawn((
        Camera3d::default(),
        Transform::from_xyz(0.0, 5.0, 10.0).looking_at(Vec3::ZERO, Vec3::Y),
    ));

    // Light
    commands.spawn(DirectionalLight::default());

    // Generate a sphere mesh
    let mesh = meshes.add(Shape::sphere(1.0, ShapeDetail::Medium).build());

    // Create a dual-directional gradient material
    let mat = materials.add(dual_directional(
        [0.6, 0.4, 0.3],  // dark color
        [0.96, 0.8, 0.69], // light color
        [0.0, 1.0, 0.0],   // gradient direction (up)
    ));

    // Spawn the shape
    commands.spawn((Mesh3d(mesh), MeshMaterial3d(mat)));
}

Character parts built from gradient-shaded primitives. Run cargo run --example character_creator to reproduce it.

Understanding the API

The core API has three main types:

  1. Shape - Describes a procedural primitive. Call .build() to get a Bevy Mesh.
  2. Style - Describes gradient material properties. Call .build_material(&mut materials) to get a Handle<GradMeshMaterial> (needs the pbr feature), or .build_2d() for a GradMeshMaterial2d.
  3. GradMeshPlugin - Registers the custom material and mesh cache with Bevy.

Features and Examples

The pbr feature is on by default and enables the lit 3D backends (GradMeshMaterial and the instanced PBR pipeline). Turn it off for PBR-free builds:

[dependencies]
bevy_gradmesh = { version = "0.3", default-features = false }

These examples run without pbr (cargo run --example <name> --no-default-features): shapes, styles, mix_spaces, curves, polyline, composed_shapes, arbitrary_shapes, gradient_2d, sdf_2d, sdf_dash_gallery and standalone. The others need pbr, which Cargo enables by default.

2D Primitives

Rectangles, discs, ellipses, rings, wedges, polygons, stars and arbitrary polygons use the SDF backend (SdfMaterial2d). Each one is a material drawn on the shared unit_quad() mesh. Polygons with holes, per-vertex colours and outlines of more than 16 vertices go through the mesh backend with Shape::as_flat()?.build_2d(). See Arbitrary Polygon on the mesh backend.

Styles & Materials

Dual-Directional Shading

The signature feature of BevyGradmesh. Colors a surface with a smooth gradient between two colors along a given direction.

use bevy_gradmesh::{GradMeshMaterial, dual_directional};
fn main() {}
fn directional_material() -> GradMeshMaterial {
    dual_directional(
        [0.6, 0.4, 0.3],   // dark color (RGB)
        [0.96, 0.8, 0.69], // light color (RGB)
        [0.0, 1.0, 0.0],   // gradient direction
    )
}

Color Spaces

Gradients blend in OKLAB by default, which avoids the muddy midpoints that RGB interpolation produces. Pick another space with with_mix_space:

use bevy_gradmesh::{GradMeshMaterial, MixSpace, dual_directional, with_mix_space};
fn main() {}
fn oklch_material() -> GradMeshMaterial {
    with_mix_space(
        dual_directional([0.6, 0.4, 0.3], [0.96, 0.8, 0.69], [0.0, 1.0, 0.0]),
        MixSpace::Oklch,
    )
}
MixSpaceBehaviour
OklabDefault. Perceptually uniform; steady lightness.
OklchSweeps hue along the shortest arc; stays vivid.
LinearRgbPhysically correct light mixing.
SrgbMixes the picker values directly; cheapest, greyest midpoints.

Style takes the same setting (Style::with_mix_space), and MixSpace::mix / Style::lerp blend on the CPU in the same space, so an animated blend matches the shader gradient. See examples/mix_spaces.rs.

Blending Styles and Shapes

Style::lerp(&other, t) mixes colors in the style’s space, interpolates continuous values and snaps discrete ones (blend mode, dash count) to the nearer end. Shape::lerp(&other, t) interpolates the parameters of two shapes of the same kind and returns the nearer shape otherwise. Every distinct blended shape is a distinct mesh, so for smooth animation prefer scaling a fixed shape.

Closed polygons (arbitrary_polygon, extruded_polygon, holes included) also morph when their vertex counts differ: both outlines are grown to the larger count by splitting their longest edges, the second is flipped to the first’s winding and rotated to the start that moves points the least, and per-vertex colours blend along (a missing list counts as white). Open point lists such as polylines and curves of different lengths still snap to the nearer shape.

Reading Shape Bounds

Shape::bounds() returns a ShapeBounds (min, max, center(), size(), half_extents(), rect_xy()) measured from the generated vertices, so it is exact for every shape kind. Shape::bounds_2d() does the same for Shape::build_2d(). Each call builds the mesh once; cache the result if you read it every frame.

Composing Shapes, 2D and Ghost Previews

Flat shapes with Mesh2d

Shape::build_2d() returns geometry in the XY plane facing +Z with gradient UVs. Pair it with GradMeshMaterial2d (built from a Style) and a Camera2d. build_2d() accepts every shape, including solids that have no flat form; call Shape::as_flat() first when you want the compiler to prove the shape is flat (it returns Err(NotFlat) for solids, tubes and meshes), then FlatShape::build_2d():

use bevy::prelude::*;
use bevy_gradmesh::{GradMeshMaterial2d, Shape, ShapeDetail, Style};
fn main() {}
fn spawn_disc(
    mut commands: Commands,
    mut meshes: ResMut<Assets<Mesh>>,
    mut materials: ResMut<Assets<GradMeshMaterial2d>>,
) {
    let mesh = Shape::disc(0.5, ShapeDetail::High).build_2d();
    let material = Style::dual_radial(Color::WHITE, Color::srgb(0.9, 0.4, 0.5)).build_2d();
    commands.spawn((
        Mesh2d(meshes.add(mesh)),
        MeshMaterial2d(materials.add(material)),
        Transform::from_xyz(0.0, 0.0, 5.0).with_scale(Vec3::splat(120.0)),
    ));
}
  • Transform scale resizes the shape on the XY plane; gradients and dashes follow because they are computed from the mesh UVs.
  • Transform.translation.z orders shapes against each other.
  • GradMeshPlugin registers the material when Bevy’s 2D mesh renderer is present. Add GradMesh2dPlugin yourself if you add GradMeshPlugin before the render plugins.
  • The material is unlit; roughness, metallic and emissive have no effect in 2D.
  • In 2D the gradient direction is expressed in the shape’s own UV frame (+Y towards the top).
  • Animate a material with GradMeshMaterial2d::with_appearance(AppearanceSnapshot::color_pulse(..)).
  • Shape::polyline_2d and Shape::bezier_2d build flat curves with thickness (u runs along the curve, v across it).

Gradient cards, a translucent dragged card layered by z, a radial disc, a pulsing star, a dashed ring and a polygon with a hole. Run cargo run --example gradient_2d to reproduce it.

Outlines, extrusion, holes

arch, rounded_rectangle and blob return counter-clockwise outlines centred on the origin.

use bevy::prelude::*;
use bevy_gradmesh::{Shape, ShapeDetail, arch, rounded_rectangle};
fn main() {}
fn wall() -> Shape {
    Shape::extruded_polygon_with_holes(
        rounded_rectangle(Vec2::new(4.0, 3.4), 0.15, 3),
        vec![arch(1.2, 2.0, 10)],
        0.5,  // depth
        0.35, // roundness of the rim
        ShapeDetail::High,
    )
}

Shape::extruded_polygon and extruded_polygon_colored handle single outlines (the colours are per vertex and multiply the gradient), arbitrary_polygon_with_holes builds the flat version. Either winding is accepted; extrusion is centred on z = 0.

Compound shapes and lathe

Shape::compound merges parts into one mesh (one draw call). Each ShapePart has a transform and an optional tint that multiplies the gradient through vertex colours, so parts keep their own gradients. Compounds are Hash + Eq and work with MeshCache.

Shape::lathe(profile, segments, detail) revolves (radius, height) points around Y. Crisp corners stay crisp, gentle ones are smoothed, and open ends away from the axis get caps.

A compound tower, a wall with an arched opening, extruded cobbles, a torch, a gem and heightfield terrain, drawn unlit by the standalone pipeline (no PBR, so no emissive, metallic or ghost pieces). Run cargo run --example composed_shapes to reproduce it.

Sharing meshes and materials

use bevy::prelude::*;
use bevy_gradmesh::{GradMeshMaterial, GradMeshMaterialPool, MeshCache, Shape, Style};
fn main() {}
fn share_assets(
    shape: &Shape,
    style: &Style,
    cache: &mut MeshCache,
    pool: &mut GradMeshMaterialPool,
    meshes: &mut Assets<Mesh>,
    materials: &mut Assets<GradMeshMaterial>,
) -> (Handle<Mesh>, Handle<GradMeshMaterial>) {
    let mesh_handle = cache.get_or_build_handle(shape, meshes);
    let material_handle = pool.get_or_add(style, materials);
    (mesh_handle, material_handle)
}

Equal shapes return the same Handle<Mesh>, equal styles (Style: PartialEq) the same material, so a per-frame sync of an unchanged node allocates nothing.

Style additions

  • Style::shaded(color, dark_factor): lit color, shadow side color * dark_factor (linear RGB).
  • with_perceptual_roughness, with_metallic, with_emissive: written to the StandardMaterial base and blended by Style::lerp.
  • with_alpha: multiplies both gradient colours’ alpha; Style::lerp fades it.

Gradient direction space

The gradient direction is a world-space vector by default: rotating the entity does not rotate the gradient. Style::with_direction_space(DirectionSpace::Local) rotates the direction with the entity’s GlobalTransform, which keeps the intended lit side for pieces built Y-up and placed in a Z-up scene by a rotation.

Ghost previews and shadows

Translucent gradient materials still render in Bevy’s shadow pass (alpha-tested only), so they cast a full shadow. Bevy decides shadow casting per entity: when style.casts_shadows() is false, add NotShadowCaster to the entity (see the composed_shapes example).

Surface detail and rim glow

GradMeshMaterial can vary the tint without textures:

  • Style::with_noise(scale, amount): smooth value noise, scale cells per local unit.
  • Style::with_stripes(direction, frequency, amount): bands along a local direction.
  • Style::with_rim(color, power): view-dependent emission towards the silhouette, for example to highlight the nearest petal of a radial menu.

Noise and stripes live in the entity’s local space, so they stay attached as it moves, turns and scales. All three are blended by Style::lerp.

Rounded roofs and gems

Shape::rounded_cone and Shape::rounded_pyramid take a roundness from 0.0 (identical to cone and pyramid) to 1.0. Shape::regular_prism already takes one. The rounded solid stays inside the sharp one, so footprints and heights are kept.

Bounds and kind

Shape::bounds() and Shape::bounds_2d() return a ShapeBounds measured from the built vertices, and Shape::is_round() tells spheres, ellipsoids, discs, ellipses and rings from other shapes, so hit tests can approximate them with an ellipsoid.

Picking

Every shape builds positions, normals, UV_0 and indices, so Bevy’s MeshPickingPlugin and the automatically computed Aabb work without custom backends. 2D shapes pick through the standard Mesh2d path.

Rendering Modes

BevyGradmesh provides four rendering modes for different use cases.

Direct Mode

The simplest approach: build a mesh and spawn it as a Bevy entity.

use bevy::prelude::*;
use bevy_gradmesh::{GradMeshMaterial, Shape, ShapeDetail, dual_directional};
fn main() {}
fn spawn_sphere(
    mut commands: Commands,
    mut meshes: ResMut<Assets<Mesh>>,
    mut materials: ResMut<Assets<GradMeshMaterial>>,
) {
    let mesh = meshes.add(Shape::sphere(1.0, ShapeDetail::Medium).build());
    let mat = materials.add(dual_directional(
        [0.6, 0.4, 0.3], [0.96, 0.8, 0.69], [0.0, 1.0, 0.0]
    ));
    commands.spawn((Mesh3d(mesh), MeshMaterial3d(mat)));
}

Best for: Static scenes with a few shapes.

Immediate Mode

Per-frame draw/dispose pattern using ImmediateRecorder. Supports push/pop state stacking and billboarding.

use bevy::prelude::*;
use bevy_gradmesh::{GradMeshMaterial, ImmediateRecorder, ShapeDetail, imm_opaque};
fn main() {}

struct Recorder(ImmediateRecorder);

fn draw_frame(
    mut commands: Commands,
    mut meshes: ResMut<Assets<Mesh>>,
    mut materials: ResMut<Assets<GradMeshMaterial>>,
    mut recorder: ResMut<Recorder>,
) {
    let recorder = &mut recorder.0;
    recorder.begin(&mut commands);

    recorder.push_state();
    recorder.set_position(Vec3::new(1.0, 0.0, 0.0));
    recorder.sphere(
        &mut commands,
        &mut meshes,
        &mut materials,
        0.5,
        ShapeDetail::Medium,
        imm_opaque(1.0, 0.0, 0.0),

}

Best for: Particle systems, animated effects, debug visualization.

Retained Mode

Persistent shapes managed by handle. Create once, update per-frame.

use bevy::prelude::*;

Batched Mode

Groups instances into batches for GPU instancing - thousands of shapes in far fewer draw calls.

use bevy::prelude::*;
use bevy_gradmesh::{AppearanceSnapshot, BatchRecorder, ShapeDetail};
fn main() {}
#[derive(Resource)]
struct Recorder(BatchRecorder);

fn draw_frame(
    mut commands: Commands,
    meshes: ResMut<Assets<Mesh>>,
    mut recorder: ResMut<Recorder>,
) {
    let recorder = &mut recorder.0;
    recorder.begin();

    for i in 0..100 {
        recorder.set_position(Vec3::new(

Choosing a Backend

BevyGradmesh can draw its shapes through five render paths. They differ in what they need from Bevy, what they can draw, and how they scale. Pick by the target first (mobile or desktop, 2D or 3D), then by the number of shapes.

BackendCameraNeeds bevy_pbrLightingBest for

Instanced (BatchRecorder, RetainedWorld)3DyesPBRThousands of similar shapes, animated appearance
Standalone (StandaloneRenderPlugin)3DnononeMobile GPUs, flat-shaded crowds, anything that must avoid PBR

Material

Shape::build() plus Style::build_material() gives an ordinary Bevy Mesh3d and MeshMaterial3d. The material extends StandardMaterial, so shadows, fog, tonemapping and mesh picking all work. MeshCache and GradMeshMaterialPool deduplicate meshes and materials.

Only this path has Style::with_height_bands.

Instanced

BatchRecorder and RetainedWorld group instances by shape and draw each group with one instanced draw call. Per-instance colour, appearance animation and deformation live in the instance buffer. Lighting comes from Bevy’s PBR functions, so it needs the pbr feature.

Standalone

StandaloneRenderPlugin draws the same batches without bevy_pbr: it uses its own camera bind group and pipeline, and finds meshes through MeshAllocator. There is no lighting, no alpha blending and no culling. It is the path to use on GPUs where the PBR pipeline is a problem (it was verified on a Mali-G715 with Bevy’s PbrPlugin disabled).

Gradient shapes drawn with one shader pipeline, no PBR material and no lights. Run cargo run --example standalone to reproduce it.

Mesh2d gradient

Shape::build_2d() returns flat geometry in the XY plane. Pair it with Style::build_2d() (a GradMeshMaterial2d) and Camera2d. Every shape kind works, but each distinct parameter set is a distinct mesh.

SDF 2D

SdfMaterial2d draws a shape from a signed distance field on one shared quad (unit_quad()). Edges are anti-aliased from screen-space derivatives, so no MSAA is needed. Radius, rim width, arc, gradient and dash are material floats: changing them creates no mesh and no pipeline.

The SDF backend draws rectangles, ellipses, regular polygons (polygon), stars (star) and polygons from up to 16 points (polygon_from_points). Rings and wedges are a disc with a rim or an arc. Polygons with holes, polylines, Bézier curves and 3D solids need a mesh backend.

Shape::as_flat() proves a shape is flat and returns a FlatShape (or NotFlat for a solid, tube or mesh). FlatShape::sdf_2d() then converts a rectangle, disc, ellipse, regular polygon and rim, star, ring, wedge, or a polygon of up to 16 vertices into the matching SdfMaterial2d, so the same shape can go to either 2D backend. It returns Err(SdfConvertError) saying why when the SDF backend cannot draw the shape (degenerate size, holes, per-vertex colours, too many vertices, a curve or compound); FlatShape::build_2d() draws all of those.

use bevy::prelude::*;
use bevy_gradmesh::{Dash2d, DashSnap, SdfMaterial2d, unit_quad};
fn main() {}
fn spawn_disc(
    mut commands: Commands,
    mut meshes: ResMut<Assets<Mesh>>,
    mut materials: ResMut<Assets<SdfMaterial2d>>,
) {
    let quad = meshes.add(unit_quad());
    let material = SdfMaterial2d::disc(80.0)
        .with_rim(10.0)
        .with_arc(0.0, std::f32::consts::PI * 1.5)
        .with_dash(Dash2d::by_length(14.0, 8.0).with_snap(DashSnap::EndToEnd))
        .with_colors(Color::srgb(1.0, 0.35, 0.25), Color::srgb(1.0, 0.9, 0.35));
    commands.spawn((
        Mesh2d(quad.clone()),
        Transform::from_scale(material.quad_scale()),
        MeshMaterial2d(materials.add(material)),
    ));
}

Gradients: with_colors (linear, along with_gradient_direction), with_radial_gradient() (fitted to the shape bounds), with_angular_gradient(start) (mirrored, no seam) and with_angular_sweep(start) (one turn, hard seam). All of them blend in the chosen MixSpace.

Dashes (Dash2d) apply to rims of rectangles and ellipses; polygons and stars draw a solid rim. Give a length and a gap in world units, or a count and a gap ratio. The snap mode decides how the pattern fits the outline:

  • Off keeps the pattern as given and cuts it where the outline starts and ends.
  • Tiling rounds the number of periods to a whole number and rescales the period, so a closed outline has no seam. It is the default.
  • EndToEnd is like Tiling on a closed outline; on a partial arc the first dash starts at the arc start and the last dash ends at the arc end.

examples/sdf_dash_gallery.rs shows every mode on discs, an ellipse, rounded rectangles and a partial arc. Two things to know: on an eccentric ellipse dashes are spaced by angle, not by arc length, and at a sharp rectangle corner the dashes meet in a mitre. Transform scale must be SdfMaterial2d::quad_scale().

Discs, ellipses, rounded rectangles, rims, animated arcs, polygons and stars on one shared quad. Run cargo run --example sdf_2d to reproduce it.

Sweeps, Meshes, Heightfields and Height Bands

These shape kinds build geometry from your data. Like every Shape they are Clone + Debug + Eq + Hash, work with MeshCache, and can be a part of Shape::compound.

Shape::from_mesh

use std::sync::Arc;
use bevy_gradmesh::{Shape, ShapeDetail};
fn main() {}
fn mesh_shape() -> Shape {
    let my_mesh = Shape::sphere(1.0, ShapeDetail::Low).build();
    Shape::from_mesh(Arc::new(my_mesh), 42)
}

Wraps a mesh you generated yourself. The shape is Eq and Hash by key only; the mesh is never compared. You own key uniqueness: two different meshes with the same key share one cache entry. Bounds and is_round() are measured from the positions once, in the constructor, so bounds() does not build anything. build() and build_2d() return a copy of the mesh, and Shape::lerp takes the nearer shape.

Shape::heightfield

use bevy::prelude::*;
use bevy_gradmesh::Shape;
fn main() {}
fn terrain_chunk() -> Shape {
    let heights = vec![0.0_f32; 17 * 17];
    Shape::heightfield(
        heights.into(),          // Arc<[f32]>, heights[x + y * size.x]
        UVec2::new(17, 17),      // samples
        Vec2::splat(16.0),       // world extent
    )
}

A terrain chunk centred on the origin in XZ, with smooth normals from central differences and UVs from 0 to 1. Skirts hang below the edges (a tenth of the larger extent) to hide cracks between neighbouring chunks of different detail; the depth is not an option, because a chunk without skirts shows cracks. Equality and hashing cover size, extent, the heights and the holes and border below, all by value, so there is no key to keep in step: changing a height gives a different shape and a stale mesh is never shared. The heights are hashed once, when the shape is built (about 4 microseconds for 65 by 65 samples), so keep the Shape and reuse it rather than rebuilding it every frame. A size below 2 in either axis, or a wrong heights length, gives an empty mesh and a warning.

Shape::bounds() includes the skirts, as it measures the mesh; Shape::surface_bounds() is the land alone. Neither builds anything.

Holes and seamless chunk edges

use bevy::prelude::*;
use bevy_gradmesh::{HeightfieldBorder, HeightfieldOptions, HoleEdge, Shape};
fn main() {}
fn chunk_with_hole() -> Shape {
    let size = UVec2::new(17, 17);
    let extent = Vec2::splat(16.0);
    let heights = vec![0.0_f32; 17 * 17];
    let holes = vec![false; 16 * 16];
    let (west, east) = (vec![0.0; 17], vec![0.0; 17]);
    let (north, south) = (vec![0.0; 17], vec![0.0; 17]);
    Shape::heightfield_with_options(
        heights.into(), size, extent,
        HeightfieldOptions::default()
            .with_holes(holes)          // Vec<bool>, (size.x - 1) * (size.y - 1) cells
            .with_hole_edge(HoleEdge::Smooth)
            .with_border(HeightfieldBorder::new(west, east, north, south)),
    )
}

A hole cell has no triangles and no skirt below it (a skirt hides seams between chunks, and a hole is meant to be see-through); vertices that only holes touch are left out of the mesh and the bounds. The border is the ring of neighbour heights just outside the chunk (west and east hold size.y heights, north and south hold size.x; corners are not needed). It is used for the normals of the edge vertices only and is never meshed, so two chunks that share an edge share its normals exactly and a crest on the border shows no crease. The mask and the border are part of the shape’s identity like the heights, so changing only them gives a different shape. A mask or border of the wrong length gives an empty mesh and a warning, like wrong heights.

Cutting the outline of a hole

The mask has one flag per cell, so the outline of a round hole can only follow cell borders: a staircase. HeightfieldOptions::with_hole_edge picks how the outline is cut, from the cheapest to the smoothest:

HoleEdgeOutlineCost
Cells (default)Whole cells: a cell is land or hole, a staircase along every curve.Two triangles per land cell.
RoundedCells that border a hole are cut through the midpoints of their edges: every staircase corner becomes a 45 degree chamfer and a one-cell hole a diamond.Up to four triangles per border cell.
SmoothThe mask is blurred over the neighbouring cells and the outline follows that, so a curved hole is cut along a curve.As Rounded, on more border cells; the outline can move by about a cell.

Only cells that border a hole cost more; every cell away from a hole keeps its two triangles at every level, so the three meshes agree there and share their edge vertices. No level ever closes a hole or removes an island of land: a one-cell hole stays a hole and a one-cell island stays land, and the cut never faces down or hangs a skirt under a hole. Without holes the option changes nothing, and it is part of the shape’s identity like the mask.

Shape::sweep

use bevy::prelude::*;
use bevy_gradmesh::{Shape, SweepOptions};
fn main() {}
fn wall() -> Shape {
    let profile = vec![
        Vec2::new(-0.2, 0.0),
        Vec2::new(0.2, 0.0),
        Vec2::new(0.2, 2.0),
        Vec2::new(-0.2, 2.0),
    ];
    let path = vec![
        Vec3::new(-4.0, 0.0, -4.0),
        Vec3::new(4.0, 0.0, -4.0),
        Vec3::new(4.0, 0.0, 4.0),
        Vec3::new(-4.0, 0.0, 4.0),
    ];
    Shape::sweep(
        profile,                      // Vec<Vec2>: x across the path, y up
        path,                         // Vec<Vec3>: a polyline or baked spline positions
        SweepOptions::default().with_closed(true),
    )
}

Sweeps a closed profile along a path as one mesh: walls, roads, rails and pipes. Frames follow the path by parallel transport from SweepOptions::up, joints are mitred (the sides keep a constant width; the mitre is clamped at four times the width), and normals are smooth along the path. A corner of the profile sharper than about 40 degrees stays crisp, gentler ones are smoothed.

SweepOptions and SweepOpening are #[non_exhaustive]: start from SweepOptions::default() and use the with_* methods, so new options never break your code.

Options:

  • closed joins the last point to the first (no caps, no seam). A closed sweep never shows a seam: a fractional twist is rounded to the nearest whole turn, and a roll_along that does not return to its start (modulo a whole turn) has the difference spread evenly along the loop.
  • caps closes the ends of an open sweep.
  • twist turns the profile, in whole turns over the path.
  • roll_along, scale_along and tint_by_length are keyframes along the path.
  • detail sets how finely long segments are split when something varies along them.
  • openings cuts gates and windows (below).

Keyframes instead of a closure

A Shape has to be Clone + Eq + Hash, which a boxed closure cannot be. So scale_along is Option<Vec<(f32, Vec2)>>: (ratio along the path, scale) pairs with linear steps in between. To start from a function, bake it:

use bevy::prelude::*;
use bevy_gradmesh::SweepOptions;
fn main() {}
fn tapering_options() -> SweepOptions {
    SweepOptions::default().scale_with(8, |t| Vec2::splat(1.0 - 0.55 * t))
}

tint_by_length is a list of (ratio, Color) pairs and multiplies the style’s colour through vertex colours.

Roll and banked roads

roll_along is (ratio, radians) keyframes with the same rules, and SweepOptions::roll_with(samples, f) fills it from a closure. Roll turns the (already scaled) profile about the path tangent, on top of the parallel-transported frame, and adds to twist.

To give the frames yourself, for example from a baked spline with its own banking, use Shape::sweep_frames:

use bevy::prelude::*;
use bevy_gradmesh::{CatmullRomSpline, Shape, SplineError, SweepOptions};
fn main() {}
fn road() -> Result<Shape, SplineError> {
    let profile = vec![
        Vec2::new(-1.0, 0.0),
        Vec2::new(1.0, 0.0),
        Vec2::new(1.0, 0.1),
        Vec2::new(-1.0, 0.1),
    ];
    let points = vec![
        Vec3::new(0.0, 0.0, 0.0),
        Vec3::new(5.0, 0.0, 2.0),
        Vec3::new(10.0, 0.0, 0.0),
    ];
    let baked = CatmullRomSpline::open(points)?
        .with_channel(&[1.0, 1.5, 1.0])   // channel 0: width
        .with_channel(&[0.0, 0.3, 0.0])   // channel 1: roll
        .bake(0.25);
    Ok(Shape::sweep_frames(
        profile,
        &baked.sweep_frames(Some(0), Some(1)),   // width channel 0, roll channel 1
        SweepOptions::default(),
    ))
}

Each SweepFrame has a position, right, up and scale. The sweep keeps them as given (no parallel transport) and blends them where it needs extra rings. The cross product of right and up should point along the path; a left-handed frame keeps its up and gets its right flipped, so the surface never turns inside out. A closed sweep joins the last frame to the first without correcting the frames at the seam.

Openings

use bevy_gradmesh::{SweepOpening, SweepOptions};
fn main() {}
fn wall_options() -> SweepOptions {
    SweepOptions::default().with_openings(vec![
        SweepOpening::arch(0.30..0.38, 0.0, 1.2, 1.9, 12),  // a gate
        SweepOpening::rect(0.60..0.64, 0.9, 1.4),            // a window
    ])
}

An opening is a real hole through the wall, with sill, lintel and jamb faces on the inside. Its outline is in wall-face coordinates, not in the profile plane: x runs 0..1 over the opening’s t range (a ratio of the path length) and y is the height above the profile origin. An outline that reaches the profile’s lowest height cuts the wall open at the bottom (a gate); one that stays inside makes a window. Outlines should be convex or cross every vertical line at most twice. Openings must not overlap along the path (a later one is ignored with a warning), and they suit profiles with one horizontal interval, such as walls, rails and kerbs, swept without twist. SweepOpening::new(t, outline) takes a custom outline.

Degenerate input never panics: fewer than two distinct path points (three when closed) or fewer than three distinct profile points gives an empty mesh and a warning. Repeated path points are dropped. On the inside of a tight bend a wide profile can overlap itself; that is not corrected.

Splines

CatmullRomSpline::closed and CatmullRomSpline::open build a curve through control points and return Err(SplineError::TooFewPoints { .. }) when there are too few (3 for a loop, 2 for a path), because the points usually come from user data. The curve is centripetal: it never swings out past a short hop between two long spans, however unevenly you place the points. An open one has one-sided end tangents and its bake puts a frame exactly on the last point. Baking never fails: a step that is not positive, or so small that it would need more than 100,000 frames, is raised to a usable one, and points that coincide bake to a tiny stretch of frames. with_channel(&[f32]) attaches a number per control point (width, roll, tilt…) that is interpolated like the position and wraps around a closed loop. bake samples every channel at every frame; BakedSpline::sweep_frames(width, roll) turns the baked frames into sweep frames.

BakedSpline::nearest_t compares in 3D, so a point on a road under a bridge matches the road. It still searches the whole curve, so where a road crosses itself within a few metres use nearest_distance_near(point, around, window) or nearest_t_in(point, range), which search only a stretch of the curve, so a kart stays on its part of the road.

relaxed(min_radius) straightens tight turns but never collapses the loop: it keeps at least half the length of the control polygon. relaxed_within(min_radius, keep) lets you choose the share and returns Err(Relaxed { best, radius }) when no curve that keeps enough length is gentle enough, so you can reject the design.

Height bands

use bevy::prelude::*;
use bevy_gradmesh::Style;
fn main() {}
fn terrain_style() -> Style {
    Style::shaded(Color::WHITE, 0.5).with_height_bands(&[
        (0.0, Color::srgb(0.35, 0.6, 0.3)),   // grass
        (1.2, Color::srgb(0.5, 0.48, 0.45)),  // rock
        (2.4, Color::srgb(0.95, 0.95, 1.0)),  // snow
    ])
}

GradMeshMaterial colours each fragment by its world height: a band’s colour holds from its height up to the next band, with a hard step and no blending. At most four bands fit (given more, the four lowest are kept and a warning is logged, the same in every build); they are sorted by height, and a fragment below the first band takes the first colour. The bands are material floats, so raising terrain does not mean re-baking vertex colours. They work on the material path only, not on the instanced, standalone or Mesh2d paths.

To state the heights as fractions of a shape’s own height, so that re-scaling the land keeps the look, use with_height_bands_on:

use bevy::prelude::*;
use bevy_gradmesh::{Shape, Style};
fn main() {}
fn relative_terrain_style(chunk: &Shape, transform: &Transform) -> Style {
    let grass = Color::srgb(0.35, 0.6, 0.3);
    let rock = Color::srgb(0.5, 0.48, 0.45);
    let snow = Color::srgb(0.95, 0.95, 1.0);
    Style::shaded(Color::WHITE, 0.5).with_height_bands_on(
        &[(0.0, grass), (0.55, rock), (0.9, snow)],   // 0 = lowest land, 1 = highest
        chunk,
        transform,                                    // the placement the chunk is shown with
    )
}

The fractions are resolved on the spot against Shape::surface_bounds() (the land, without skirts) and the transform into ordinary world heights, so an unresolved band can never reach the shader. Build the style again when the heights or the placement change. Neighbouring chunks only agree on colour at their shared edge with the absolute form, because each chunk has its own range.

Morphing

Shape::lerp also morphs filled flat shapes of different kinds (rectangle, disc, ellipse, regular polygon, star and arbitrary polygon) as outlines, and SdfMaterial2d::lerp blends two SDF shapes (a circle becomes a rectangle through its corner radius).

Bézier Curves

Render smooth curves as tube geometry:

use bevy::prelude::*;

fn curve_mesh() -> Mesh {
    let control_points = vec![
        Vec3::new(0.0, 0.0, 0.0),

Using with BatchRecorder

use bevy::prelude::*;
use bevy_gradmesh::{BatchRecorder, DeformationParams, ShapeDetail};
fn main() {}
#[derive(Resource)]
struct Recorder(BatchRecorder);

fn draw(
    mut commands: Commands,
    meshes: ResMut<Assets<Mesh>>,
    mut recorder: ResMut<Recorder>,
) {
    let recorder = &mut recorder.0;
    recorder.begin();

    recorder.set_deformation(
        DeformationParams::wobble(0.15, 3.0, 0.0)
    );
    recorder.set_position(Vec3::ZERO);
    recorder.sphere(0.5, ShapeDetail::Medium, [1.0, 0.0, 0.0, 1.0]);

    recorder.end();
    recorder.render_batches(&mut commands, meshes, None);
}

How It Works

  1. Each instance carries a DeformationParams vec4 in its GPU buffer
  2. The vertex shader reads this attribute and displaces vertices in local space
  3. The global Deformation resource provides elapsed time for animation
  4. All computation happens on the GPU - no CPU overhead per frame

Performance

Deformation is free for batched instances since it runs entirely in the vertex shader. No additional draw calls or CPU work is needed.

Using with BatchRecorder

use bevy::prelude::*;
use bevy_gradmesh::{AppearanceSnapshot, BatchRecorder, ShapeDetail};
fn main() {}
#[derive(Resource)]
struct Recorder(BatchRecorder);

fn draw(
    mut commands: Commands,
    meshes: ResMut<Assets<Mesh>>,
    mut recorder: ResMut<Recorder>,
) {
    let recorder = &mut recorder.0;
    recorder.begin();

    for i in 0..50 {
        recorder.set_position(Vec3::new(
            (i % 10) as f32 * 2.0,
            0.0,
            (i / 10) as f32 * 2.0,
        ));

        // Each instance animates with a different phase
        recorder.set_appearance(
            AppearanceSnapshot::color_pulse(2.0, i as f32 / 50.0)
        );

        recorder.sphere(0.3, ShapeDetail::Medium, [1.0, 0.0, 0.0, 1.0]);
    }

    recorder.end();
    recorder.render_batches(&mut commands, meshes, None);
}

How It Works

  1. Each instance carries an AppearanceSnapshot vec4 encoding speed, phase, and type
  2. The vertex shader resolves the animated color at render time using global time
  3. Different phase values create staggered animation across instances
  4. No per-frame CPU updates needed - the GPU handles all animation

Performance

Appearance animation is free for batched instances. The animation parameters are uploaded once with the instance data, and the vertex shader computes the animated color each frame.

Level of Detail

Automatic distance-based LOD with dither cross-fade eliminates pop-in when shapes change detail level.

How It Works

  1. Each frame, the camera distance to each batch is computed
  2. Based on distance, an LOD level (0 to 4) is selected
  3. During transitions, both LOD levels render simultaneously with a Bayer dither mask
  4. The dither pattern smoothly fades between levels, eliminating visual pop-in

Configuration

use bevy::prelude::*;
use bevy_gradmesh::LodConfig;
fn main() {}
fn configure_lod(mut commands: Commands) {
    let lod_config = LodConfig {
        // Distances where each level hands over to the next, nearest first
        thresholds: [5.0, 20.0, 50.0, 100.0],
        transition_width: 3.0, // Distance range for cross-fade
        hysteresis: 0.2,       // Prevents LOD flickering (0.0 to 1.0)
    };
    commands.insert_resource(lod_config);
}

Custom Pipeline

The Problem with ExtendedMaterial

By default, BevyGradmesh uses GradMeshMaterial, which is implemented as ExtendedMaterial<StandardMaterial, GradMeshExtension>. This means every unique material instance triggers a new shader specialization via Bevy’s PBR pipeline. Each specialization allocates new descriptor sets.

On mobile GPUs (e.g., Android Mali-G715), the Vulkan descriptor pool fragments after ~20-30 such allocations, causing VK_ERROR_FRAGMENTED_POOL and a wgpu panic. Even with GradMeshMaterialPool deduplication, adding many materials can push past the limit.

The root issue: ExtendedMaterial inherits the entire PBR pipeline, including lighting, shadows, prepass, deferred rendering, and meshlet support - none of which GradMesh uses. Gradient shading is a simple two-color vertex shader that doesn’t need PBR at all.

The Standalone Pipeline

The standalone pipeline (StandaloneRenderPlugin) bypasses Bevy’s PBR system entirely. It uses a pure WGSL shader (standalone.wgsl) with no Bevy PBR imports, where all material variation comes from per-instance vertex attributes rather than shader specialization.

Key Benefits

  • Zero descriptor pool pressure - One pipeline, one bind group layout, one descriptor set
  • No PBR overhead - No prepass, no shadows, no deferred rendering
  • Mobile-friendly - Works on Mali-G715, Adreno, and any GPU with limited descriptor pool capacity
  • Faster compilation - One shader pipeline instead of N specializations

Architecture

StandalonePipeline
|-- Single render pipeline (no specialization per material)
|-- Reuses Opaque3d binned render phase
|-- Per-batch vertex buffer (transforms + properties)
+-- Standalone WGSL shader (no PBR imports)

Usage

The standalone pipeline is automatically enabled when you add GradMeshPlugin:

use bevy::prelude::*;
use bevy_gradmesh::GradMeshPlugin;
fn main() {}
fn add_plugin(app: &mut App) {
    // GradMeshPlugin includes StandaloneRenderPlugin by default
    app.add_plugins(GradMeshPlugin);
}

To use the standalone pipeline for rendering, use render_standalone_batches() instead of BatchRecorder::render_batches():

use bevy::prelude::*;
use bevy_gradmesh::{BatchRecorder, ShapeDetail, render_standalone_batches};
fn main() {}

fn render(mut commands: Commands, meshes: ResMut<Assets<Mesh>>) {
    let mut recorder = BatchRecorder::new();
    recorder.begin();

    recorder.set_position(Vec3::ZERO);
    recorder.sphere(0.5, ShapeDetail::Medium, [1.0, 0.0, 0.0, 1.0]);

    recorder.set_position(Vec3::X);
    recorder.sphere(0.5, ShapeDetail::Medium, [0.0, 1.0, 0.0, 1.0]);

    // Use standalone pipeline - no PBR, no descriptor pool pressure
    recorder.end();
    let _entities = render_standalone_batches(&mut recorder, &mut commands, meshes, None);
}

The standalone pipeline: one shader pipeline and one bind group. Run cargo run --example standalone to reproduce it.

When to Use Which

  • Use the PBR pipeline (InstancedBatchData) when you need lighting, shadows, or deferred rendering integration
  • Use the standalone pipeline (StandaloneBatchData) for mobile targets, large scenes with many materials, or when you only need gradient shading without PBR

Limitations

  • No PBR lighting or shadows
  • No deferred rendering support
  • No meshlet support
  • Gradient shading computed in world space (not object space)

Physics Integration

BevyGradmesh meshes work with any Bevy physics plugin. Read the vertices and triangles from the built mesh and pass them to the plugin’s trimesh or convex hull constructor:

use bevy::prelude::*;
use bevy_gradmesh::Shape;
fn main() {}
fn collider_data(shape: &Shape) -> Option<(Vec<Vec3>, Vec<[u32; 3]>)> {
    let mesh = shape.build();
    let positions = mesh.attribute(Mesh::ATTRIBUTE_POSITION)?.as_float3()?;
    let vertices: Vec<Vec3> = positions.iter().map(|p| Vec3::from(*p)).collect();
    let indices: Vec<u32> = mesh.indices()?.iter().map(|i| i as u32).collect();
    let triangles = indices.chunks_exact(3).map(|t| [t[0], t[1], t[2]]).collect();
    Some((vertices, triangles))
}

Performance Tuning

  1. Use batched mode for large numbers of similar shapes
  2. Enable LOD for scenes with varying camera distances
  3. Check dirty tracking to minimize GPU uploads
  4. Use appropriate detail levels - don’t use Extreme for distant objects
  5. Monitor InstancedStats each frame during development

Limitations

  • No Order-Independent Transparency (OIT)
  • No planar reflections
  • No visual editor integration (Bevy has no editor)
  • NURBS curves not supported (only cubic Bézier)
  • No secondary LOD membership during transitions
